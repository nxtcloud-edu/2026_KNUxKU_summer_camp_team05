# 문서 권위와 변경 규칙

- 문서 버전: v1.0 / 2026-08-14
- 적용 범위: MOA MVP 설계·구현·운영 문서

## 권위 순서

충돌이 생기면 아래에서 먼저 나오는 항목을 따른다.

1. [Accepted MVP ADR](../adr/README.md)
2. `packages/contracts` 스키마, 구현 코드, 통과한 테스트가 증명하는 현재 동작
3. 이 폴더의 운영 게이트와 실행 절차
4. 루트 README의 범위·시작 안내
5. 종합 기획서, Agent 아키텍처, Survey와 공급자 정책의 목표 설계
6. 카테고리 구현 메모와 prototype README
7. 브랜치 스냅샷·과거 초안

코드가 ADR과 다르면 코드가 옳다는 뜻이 아니라 **현재 구현이 결정에 미도달**한 것이다. 현재 동작 설명에는 코드를, 구현 방향에는 Accepted ADR을 따른다.

## 상태 표기

새 문장과 변경 PR은 필요한 경우 다음 중 하나를 붙인다.

- `현재 사실`: 이 커밋과 검증 증거로 관찰됨
- `MVP 결정`: Accepted ADR이 요구함
- `목표 설계`: 현재 MVP 이후의 방향
- `보류`: 사용자 또는 외부 공급자 확인 전에는 진행하지 않음
- `범위 밖`: 현재 MVP에서 구현·완료를 주장하지 않음

## 충돌 처리

1. 충돌 문장을 삭제해 숨기지 말고 현재 사실과 목표를 분리한다.
2. 제품 권한·상태·데이터 계약 충돌은 ADR을 먼저 갱신하거나 새 ADR을 만든다.
3. 모델 ID, 가격, API 약관처럼 변하는 값은 확인 날짜와 출처를 붙인다.
4. 구현 문서는 실제 코드·테스트보다 앞서 완료를 주장하지 않는다.
5. README에는 상세 정책을 복제하지 말고 권위 문서로 연결한다.

## 변경 책임

ADR 변경은 결정 이유와 영향을 남기고, 계약 변경은 fixture와 테스트를 함께 갱신한다. 출시 상태 변경은 [MVP 출시 게이트](mvp-release-gates.md)의 라벨과 증거를 사용한다.
